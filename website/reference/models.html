Docs/Reference/4. Models

4. Models

Reference · docs/reference.md

c
WEBC_MODEL(Todo,
           (id, i64, .pk = true),
           (title, str, .required = true, .max = 200),
           (tags, VecStr, .json_array = true),
           (owner, Account),
           (secret, str, .sensitive = true, .no_json = true))

The macro generates the struct, a descriptor table (Todo_modelof()), the table name (todos — snake_case plural, override with WEBC_MODEL_TABLE(Todo, "todos2")), and works for all of:

c
model_to_json(a, Todo_modelof(), &t);
model_from_json(a, Todo_modelof(), body, &t);
model_from_form(a, Todo_modelof(), body, &t);
model_validate(Todo_modelof(), &t, &errs);
db_insert(db, Todo, &t);

Qualifiers (all designated initialisers, so the compiler checks them):

qualifiermeaning
.pk = trueprimary key; an integer pk is assigned by the database
.required = truemust be present and non-empty
.not_null = truesame, spelled for rows rather than bodies
.unique = truedeclared in generated SQL; enforced by the database
.max = N / .min = Nstring length bounds
.gte = X / .lte = Xnumeric bounds
.format = "email"email, uuid, url, date
.trim = truestrip surrounding whitespace before validation
.sensitive = trueredacted by the logger
.no_json = truenever serialised
.json_array = truea vector field serialises as an array of scalars
.sql = "column"column name override
.def = "..."SQL default expression
.doc = "..."surfaced by webc doctor
.null = truean integer column that is NULL-able; 0 is how this side spells NULL
.references = "media_assets(id)"the FK target, written into the generated DDL

Bare flags (.required with no = true) are not valid C; write .required = true.

A column that can be absent says so once. .null is for an integer kind — the one kind whose zero is not a value of its own — and it means the three things a nullable foreign key needs at once:

c
WEBC_MODEL(Post,
           (id, i64, .pk = true),
           (cover_media_asset_id, i64, .null = true, .references = "media_assets(id)"))

db_save(Post, &p);                       // 0 becomes SQL NULL, not a row pointing at nothing
ww_is_null(&w, Post, cover_media_asset_id);   // where the column is NULL
ww_not_null(&w, Post, cover_media_asset_id);  // and where a cover was chosen
  • the DDL carries references media_assets(id) and no not null;
  • db_save binds SQL NULL when the field is 0, and reads NULL back as 0;
  • the JSON encoder writes null (and accepts null on the way in only for this field);
  • an empty form input is the browser's way of saying "nothing chosen", so it becomes 0.

.null on a f64, an enum or a Text is a compile error, and so is .null together with .required or .pk: a float's 0 is a value, an enum's 0 is its first member, and a primary key that could be NULL is not one. The workaround this replaces was a hand-written table rebuild, because sqlite cannot drop a constraint — the app in the review had exactly that migration.

A model holds up to 64 fields, which is the number of slots the preprocessor machinery (WC_MAP_S_*, generated by tools/gen_pp.py) has. It was 32, and the 33rd field reported "pasting formed WC_MAP_S_(" — a message about a macro, explained (confidently, wrongly) as a fault in the field it named. A row this wide is usually two tables: long prose belongs in its own row and its own screen.

A closed set is a field, not a Text you validate by hand. WEBC_ENUM declares the set; a field of that type is an int in the struct and its name everywhere bytes are exchanged — JSON, forms, SQL text — and a request that sends a stranger is a 422 naming the field, not a row that silently renders nowhere:

c
WEBC_ENUM(Lane, backlog, todo, doing, done)
WEBC_MODEL(Card, ..., (lane, Lane, .required = true))

Card c = {.lane = todo};                 // the C name
Lane_index(str_lit("doing")) == 2;       // helpers carry the type's name
Lane_name(3) == "done";

The generated T_N, T_index(), T_ok() and T_name() are all compile-checked against the declaration; an integer column still reads (as its index).

A row you computed is still a row. WEBC_ROW declares a shape for JSON, a vector and a view, with no table behind it — the KPI, the dashboard line, the "count by referrer" that every admin page builds out of a select:

c
WEBC_ROW(CountRow, (key, Text), (value, i64))      // no table, no migration, no pk

static VecCountRow counts;                          // in webc_boot(): VecCountRow_with(app_arena())
push(counts, ((CountRow){.key = "google", .value = 12}));
for_each(r, counts) { el("li") { text("%s: %lld", r->key, (long long)r->value); } }
json(200, &counts);                                 // and it serialises like any collection

It is WEBC_MODEL + WEBC_MODEL_INTERNAL, which is what the schema check already skips, so the only difference is the name: db_save on a WEBC_ROW panics with a sentence instead of sending an insert at a table that does not exist. Without it, a computed row is either a WEBC_MODEL that makes webc check report drift forever, or a hand-written Vec of a struct the JSON encoder cannot see.

Two models and a key between them is a relation, and it is declared next to the fields it names — WEBC_MODEL_REF(Story, section, Section, slug) and the reverse WEBC_MODEL_MANY(Section, stories, Story, section). That declaration is the only place the foreign-key column is written; prefetch reads it, ref()/refs() read the links, and db_save_all fills the key. §9a2 and §9a3 are the whole story; the guide The ORM is the walk through.

4a. Documents: several collections under one wire shape#

A model is a row; a document is the shape a live page sends — several collections and scalars in one JSON object, one declaration for both directions:

c
WEBC_DOCUMENT(BoardDoc,
              (me,      User),        // one row, written nested; a missing key
              (users,   VecUser),     // on the way in leaves it zeroed
              (online,  VecI64),
              (cards,   VecCard),
              (chat,    VecChatMsg))

str  j = BoardDoc_write(a, &d);        // both directions generated; the fields
bool ok = BoardDoc_read(a, j, &out);   // are checked by the compiler, so a new
                                      // field is one edit, not five

Field types may be models, vectors of models, vectors of scalars, enums (by name) or the scalar kinds — everything the model codec checks applies. On the client, a document arrives through a store (§11b): WStore owns the two generations a streaming page needs, and wc_doc_join() links relations (below) after a read.

Relations inside a document. WEBC_MODEL_REF(Card, assignee, User, id) declares the link as always; on the server prefetch() fills it in one query; on a client that decoded a document, the join is in-memory:

c
BoardDoc *d = store_read(&room, json);
wc_doc_join(store_arena(&room), Card_modelof(), &WC_VECDESC_VecCard, &d->cards,
            "assignee", User_modelof(), &WC_VECDESC_VecUser, &d->users);
const User *u = ref(Card, k, assignee);   // both halves, one spelling

Where a model stores an ISO timestamp as text (the common case; asking the app to parse it into milliseconds first is what makes every app carry its own calendar), the shared half has the patterns:

c
fmt_date_iso(st->published_at, "%e %B %Y")   // "11 October 2026"  (a str)
fmt_date_iso(st->published_at, "%e %b")      // "11 Oct"
fmt_date_iso(st->published_at, "%H:%M")      // "09:40"
fmt_date_iso(now(), "%A, %e %B %Y")          // "Sunday, 11 October 2026"

"2026-10-11" and "2026-10-11T09:40:00Z" both parse; a bad value gives "" and never panics. The pattern language is %Y %m %d %e %b %B %a %A %H %M %S %% — %e is the day without a leading zero, %B/%A the long names. fmt_date() is the same for a time_t.

c
read_minutes(body)        // 220 words a minute, rounded up, never zero
read_time(body)           // "4 min read"
name_from_slug(slug)      // "ada-lovelace" → "Ada Lovelace"
contains_ci(hay, needle)  // ASCII case-insensitive substring
title_case(s), slugify(s)

All of them take a str, a Text or a C string and return a str (except read_minutes, which returns an i32). They live in <webc/url.h>, which shared.h includes, so the server and the browser half spell a date the same way — the alternative was a month table in each, which is what The Meridian had.

The codec links in the browser half too — it always did; the comment that claimed otherwise cost real apps a hand-mirrored decoder whose field names no compiler checked. The browser-half spellings zero out first, so a partial document cannot leave a stale field behind:

c
JParse p = json_parse(a, frame);            // the generation arena is current
JVal *fl = json_get(p.v, "flights");
for (i32 i = 0; fl && i < fl->n; i++) {
  Flight f;
  if (model_read_json_val(a, Flight_modelof(), fl->items[i], &f) && f.id)
    push(g_flights, f);
}
