3. Collections

Reference · docs/reference.md

c
Vec(Todo)                      // → the type VecTodo, carrying its descriptor
static VecTodo todos;

push(todos, (Todo){.title = "write it"});   // every verb takes the vector
len(todos); at(todos, 0)->title;            // reads
remove_at(todos, 0);                        // keeps order
for_each(t, todos) { text("%s", t->title); } // keyed by .pk, no callbacks

WEBC_MAP_DEFINE(MapStrI64, map_str_i64, str, i64)
map_str_i64_put(&m, str_lit("a"), 1);   // keys compared by content for str

The descriptor lives inside the vector, so a collection names its element type at run time: json(200, &todos) needs no model argument, and for_each needs no key expression. db_all(Todo) returns a VecTodo * built the same way.

The five primitive collections are prelude types, and vec_new() speaks their spelling. VecI64, VecI32, VecF64, VecStr and VecBytes are declared by the framework, so an empty collection of numbers is one call rather than a hand-declared type:

c
VecStr *names = vec_new(str);        // the same type as VecStr
VecI64 *ids   = vec_new(i64);        // and as VecI64
VecF64 *means = vec_new(f64);        // a collection of pointers: vec_new(Story) → VecStory

vec_new() builds its type name by pasting Vec onto its argument, which spells str as Vecstr — a type nobody declared, so the one call every empty list needs did not compile and apps wrote the three lines by hand. The paste now lands on the prelude's own type. The other direction is a redeclaration (Vec(str) would declare Vecstr a second time), so a primitive collection is named, never re-declared: Vec(i64) is what webc lint reports.

The argument is the collection, not its address. A value goes as &todos, a VecTodo * from db_all() goes as it is — one & too many is a VecTodo **, and that reads the pointer's own bytes as a descriptor and kills the process inside the writer. json_list(200, v) is the spelling that cannot be got wrong: it reads v->desc and v->at, so a pointer-to-pointer is a compile error naming the type (member reference base type 'VecTodo **' is not a structure), and json() grew a magic word in the descriptor so a wrong argument is a 500 with a sentence instead of a crash.

Querying is the first answer to "which rows?", and db_all_where() is how you ask. For the collection you already have — grouped by desk, most-read first — two macros, both keyed on a field so the compiler and the model descriptor check the name:

c
VecStory *mine = vec_new(Story);                        // an empty collection, current arena
VecStory *desk = vec_where_str(&site->stories, Story, section, slug);
VecStory *live = vec_where_bool(&site->stories, Story, published, true);
sort_desc(desk, Story, views);                          // stable, by views, descending
sort_by(desk, Story, published_at);

vec_where_str / _i64 / _bool return a new collection of the same type; the comparison follows the field's WKind, so a Text field compares as text and an i64 as a number.

The pointer spellings — vlen(rows), vat(rows, i), and the typed walk each(f, rows) { … f->number … } — take the Vec * the caller actually holds, so the value forms' at((*rows), i) / len(*rows) dance disappears from list views.
