8. Middleware

Reference · docs/reference.md

c
typedef bool (*mw_fn)(Request *req, void *ctx, WNext *next);   // false = stop the chain

Built in: mw_logging, mw_request_id, mw_headers(HeadersCfg) (the CSP, nosniff, …; mw_headers_default() is mw_headers((HeadersCfg){0}) and its policy is default-src 'self'; img-src 'self' data:; style-src 'self' 'unsafe-inline'; script-src 'self' 'nonce-<per request>' 'wasm-unsafe-eval' — the nonce is put on every <script>/<style> of an HTML response as it is written, and wasm-unsafe-eval is there because without it the browser refuses to instantiate the module mw_web_assets serves), mw_cors(&(CorsCfg){...}), mw_body_limit(bytes), mw_timeout_ms(ms), mw_auth_bearer(token), mw_recover, mw_static(prefix, dir), mw_static_spa(prefix, dir), mw_metrics, mw_dev(port), mw_compress(), mw_document() and mw_not_found(file) (both below).

8a. The policy is a value: mw_headers()#

The default CSP is one string with three parts, and a project that needs a CDN in img-src would otherwise splice the header by hand. It is a struct, and webc.json reaches the same struct:

c
webc_use(mw_headers((HeadersCfg){
    .img_src = (const char *[]){"'self'", "data:", "https://cdn.example.com"},
    .img_src_n = 3,
    .extra = "frame-ancestors 'self'; form-action 'self'",
}));
json
"csp": {"img_src": ["'self'", "data:", "https://cdn.example.com"],
        "script_src": ["'self'", "'wasm-unsafe-eval'"],
        "no_default": false}

One policy, not two. webc_main() installs mw_headers() from the csp block after webc_boot(), so the framework's copy is inside the app's chain and — on the way out — writes first. A project that registers its own mw_headers() therefore replaces the framework's default rather than stacking beside it: webc_install_default_middleware() skips any default whose .name the app already registered (§8b). Without that rule the HeadersCfg above would be built, applied, and then overwritten by the policy from webc.json — a CDN list in C that never reached a browser.

img_src and script_src replace the default lists (script_src without a nonce entry means the nonce is not offered, which is what an app with no inline script wants), extra is appended verbatim, and no_default says the app writes the header itself — the framework then emits none. A handler may still choose the policy for its own response with res_header(); mw_headers() defers to a policy that is already there.

The devtools panel. WebC.devtools() (or ?__webc_devtools on the URL) opens a small panel in the corner of the page: the bridge's own numbers — ops, bad ops, hydrated, anchors, created elements — refreshed live, plus WebC.why() as a mode you arm and click. It is dev.js, not a bridge verb: nothing an app ships knows it exists.

webc dev widens the policy that is in force rather than building one of its own, so whatever the app declared — in C or in webc.json — is what a browser sees in development too, with the reload additions ('unsafe-inline', ws://localhost:<port>, dev.connect). That distinction is worth a sentence, because a dev server that builds its own policy from scratch makes an img-src with a CDN in it hold in production and silently stopped holding under webc dev. The dev server widens whatever policy is in force with what live reload needs ('unsafe-inline', ws://localhost:<port>, the origins in dev.connect), so a strict policy costs nothing in development. res_header_get(res, "Content-Security-Policy") reads one back, which is what an app that rewrites its own needs; wc_csp_build() is the builder on its own, for a project that emits the header outside a response.

8b. Order: the document is finished before anything compresses it#

mw_document() is the framework's own last-installed (innermost) middleware, and it exists because of a bug worth understanding before changing the chain. A page's <head> — the title, the description, the OG tags — is collected in the request while the view runs and spliced into the body on the way out. When that splice ran at the socket, mw_compress() had already turned the body into gzip bytes; searching compressed bytes for </head> finds nothing, so the splice silently did nothing for every client that sends Accept-Encoding: gzip — which is every browser — while curl without that header got the head and every smoke test passed.

So the splice happens while the body is still HTML: mw_document() runs inside the router's response, before mw_dev appends the reload script and before gzip. Two rules follow:

  • Register it last, so it wraps the route: `webc_use(mw_compress()); webc_use(mw_document());

    ...routes...`.

  • Anything that appends to an HTML body goes outside it. mw_dev does: the reload script

    is added after the head is applied, and it carries the page's nonce itself because the policy names the nonce and the dev script is the framework's own inline script.

A project rarely writes the chain at all: webc_main() calls webc_install_default_middleware() after webc_boot() (compress, dev, request id, headers, logging, recover, body limit, web assets, static, document, 404), so webc_boot() registers only what it adds. A default is skipped when the app registered one with the same .name — the singleton rule of §8a — so "my own logging" or "my own policy" is one webc_use() in webc_boot() and never a second log line or a second header. static and the rest are additive: /public and /uploads are different files, so both are installed.

8c. A 404 that is a page#

The default answer to a URL nobody routed is a JSON error. A project that wants a real page for a browser names the file once:

json
"not_found": "public/404.html"

mw_not_found() then answers a 404 that accepts HTML with the file's markup inside the app's own shell — title, theme and nonce included — and leaves everything else alone: a route that answered 404 with HTML keeps its own page, and a client that sent Accept: application/json still gets the JSON error. A file that is a whole document (<html …>) is served as it is.

gzip#

On by default. mw_compress() is the first middleware the framework installs (install_default_middleware), so every response the client said it accepts goes out as Content-Encoding: gzip — static files and rendered bodies: a JSON API shrinks by 70%, a server-rendered page by 60-80%, a wasm module by 58%. WEBC_NO_GZIP=1 turns it off, for an app that ships its own compressed bytes or sits behind something that compresses.

It is a normal middleware, so an app may take it out of the default chain and put it where it wants — in front of the middlewares that answer, so it wraps their response:

c
webc_use(mw_compress());
webc_use(mw_static("/public", "public/"));

What it will not do, and why:

  • Compress what gzip does not help. Only text/*, JSON, JavaScript, XML, wasm and

    SVG are eligible — not text/event-stream, not PNG, not woff2. A file under WC_GZIP_MIN (1 KB) is left alone: the 18-byte wrapper costs more than it saves.

  • Compress a 206. A byte range is answered from the disk as the identity bytes (§7e):

    Content-Range counts bytes of the representation the client asked about, so compressing it would both lose the offsets and read a whole file into memory to serve its first kilobyte. 206 and 416 are skipped exactly like 204/304.

  • Decide by itself whether the client wants it. No Accept-Encoding, gzip;q=0 or

    identity gets the bytes as they are. Vary: Accept-Encoding goes on every response that could have been compressed, so a shared cache never crosses the two.

  • Reuse a validator across the two encodings. The gzipped representation carries

    <etag>-gz, so If-None-Match from a gzip response is answered with a 304, and one from an identity response is not answered with a gzip 304.

  • Compress a file twice. Files are cached by (path, size, mtime) — 32 of them by

    default — so a 155 KB module is compressed once and served from memory after that. mw_compress_opts((CompressOpts){.level = 6, .slots = 8}) tunes it; level 9 (default) is the smallest bytes, and it is zlib doing it, so it matches gzip -9.

Because it is first, it is the last word on every body: whatever a middleware or a route wrote is what gets compressed. That is also why the page's <head> is spliced inside it (§8b) — a splice after this one searches gzip bytes and finds nothing.

webc serve and webc dev both serve through it (§13b), so the bytes you measure in a browser are the bytes that ship.

The -lz on every link line is this feature and only this feature: webc build adds it to the app's link, because the framework's own default chain references the middleware. zlib is on macOS and on every Linux worth deploying to; a platform without it is a platform where WEBC_NO_GZIP=1 does not help, and the fix is a -lz-shaped one.

Global middleware runs for unmatched paths too — that is how static files and the dev reload script exist without being routes.

A chain carries up to WC_MW_MAX (32) middlewares, globally, per group and per route, and the dispatcher runs every one of them — the same number in both places, because a registered middleware that never runs is the worst kind of silent failure. Going over the limit prints one line naming WC_MW_MAX instead of dropping the extra one. The framework's own defaults use ten of the thirty-two (compress, dev, request_id, headers, logging, recover, web-assets, static twice, document, and not_found when webc.json names a file), so an app registers into an empty argument, not a race.
