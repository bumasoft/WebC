Reference: how to read it

The reference is the framework's own manual: sixteen sections, in the order the framework is built, with every macro, every limit and every deliberate deviation written down. It is also the same text that ships in the repository (docs/reference.md) and that webc lint checks for retired names.

Read it in three ways.

As a book. Start at §1 House rules and keep pressing next. The sections build: strings and arenas, collections, models, HTTP, the database, then the frontend in three parts (signals, DOM, the bridge), then the CLI, testing, ops and the limits.

As a lookup. Everything is one page per section, so the browser's find is usually enough; or press <kbd>/</kbd> and search — the index covers every heading and every paragraph.

As the contract. The reference states what is implemented and covered by tests, and says so when something is not. Where a choice is surprising, it says what the choice costs, in the same paragraph that makes it.

13The browser bridgewasm, hydration, js(), the host, the boot block

15Opslogs, metrics, /debug, limits, config
16Limits and deviationswhat is not implemented, and what is not going to be

Reading a section that says "not implemented". Those sentences are part of the contract. The framework would rather name a gap than leave you to find it in production.
