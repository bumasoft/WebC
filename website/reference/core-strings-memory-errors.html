2. Core: strings, memory, errors

Reference · docs/reference.md

c
str s = str_lit("hello");            // a (pointer, length) pair, never NUL-terminated for you
Text t = fmt("%d-%s", 42, "x");       // formatted into the current arena
str trim = str_trim(s);
bool eq = str_eq(s, t);              // by content
i64 n; str_to_i64(str_lit("42"), &n);
str esc = json_escape(a, raw);       // a complete JSON string literal, quotes included

Types: i8..i64, u8..u64, f32, f64, bool, str, Bytes.

Memory. An arena is a chunked bump allocator; arena_reset is O(1) and keeps the memory. The framework installs one per scope — the process, the request, the render — so application code never creates or resets one. wm_alloc / wm_free is the raw heap with a 16-byte header, byte accounting (wm_stats()), and an optional hard limit (wm_set_limit); that is what the framework itself uses. Allocating arena memory with wm_free is a panic, on purpose.

What to use in an app, instead of an arena:

c
Text s = fmt("%s/%lld", prefix, (long long)id);  // lives for this scope
str  v = fmt_s("%s/%lld", prefix, (long long)id); // the same, as a str: no conversion needed
Text t = text_of(some_str);                       // a str -> Text: a NUL-terminated copy
str  w = WC_AS_STR(s);                            // a Text, a str or a literal -> str, no copy
Text keep = persist(s);                           // lives for the process

There are two string types and they are both ordinary: Text is a char * that fmt() returns and that markup helpers accept, and str is a {ptr, len} slice that model fields, routes and get() on a state(Text, …) use. Crossing between them is one macro each way — WC_AS_STR to go to a str, text_of or fmt_s to go to a Text — and every markup helper in §12 already takes either, so class_(fmt(...)) needs nothing at all.

The four spellings, and what happens when you pick the wrong one. Four types is the thing people trip over, and the trip is always the same: a value that is one type, a place that wants another, and a compiler message about a struct. This is the whole table, and the third column is the message you get — which is the part a cheat sheet usually leaves out:

wherewhat it acceptsif you get it wrong

text("%s — %s", a, b)two or more arguments: the first is a printf format, the rest are valuesa % you mean literally is written %% here. With one argument there is no format at all, so text("50% off") is exactly those bytes

The rule behind the table: anything that writes text takes any string (str, Text or a literal), and a wc_*_c name means exactly const char *. The conversion is always one macro — WC_AS_STR in, text_of/fmt_s out — so the fix is mechanical once the error is read as "wrong spelling", which is what the third column is for.

WEBC_STRICT_LIFETIME=1 mprotects a scope arena when it dies, so a Text used past its scope crashes in development instead of showing yesterday's bytes.

Errors.

c
WErrRes r = do_thing();
if (!r.ok) return r;
tryv(do_thing());            // return early, propagating the error
try(x)                       // unwrap a Result, returning the error from the enclosing fn
errdefer(free_it, buf) { ... }  // runs only when the block leaves through a failed try
  • The message is stored in the error (WErr.buf, up to WC_ERR_MSG_CAP bytes;

    longer messages are truncated and truncated is set). A WErr you keep past the arena that raised it still reads correctly, and copying the error copies the message. Read it with werr_msg(&e) — a str into the error, so the error must outlive it — or printf("%.*s", WERR_FMT(e)). detail is the exception: it is request context and is borrowed.

  • errdefer's "did this block fail" counter lives in the task, like the panic frame

    and the current arena, so a try() that fails before an await and the errdefer that runs after it agree even when the task resumed on another worker.

panic(...) prints, then unwinds to the nearest wc_try_begin frame if one is installed — which is how the recover middleware turns a panic into a 500 instead of killing a worker.

A 500 says where it happened. The body is still a flat {error, message}, and the message carries the request: internal error — GET /a/x (route /a/:slug, id 6f1c…). A fail(500, …) keeps its own sentence in that place; a genuine panic stays internal error so a broken handler cannot leak its internals to a stranger. The route, the method and the id are not internals — they are what makes the report usable — and the same four fields open the log line and the crash report's first line, so a crash-*.txt names the request it crashed in.
